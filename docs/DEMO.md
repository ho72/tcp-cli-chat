# 동작 확인 기록

[프로젝트 소개](../README.md) · [설정과 실행](SETUP.md)

2026.10.06에 macOS, Python 3.14.6 환경에서 이 저장소의 실제 서버와 두 클라이언트를 `127.0.0.1`에 연결해 확인했습니다. 테스트 계정의 비밀번호는 실행 중 생성한 임시 값이며 소스나 아래 기록에 포함하지 않았습니다.

## 두 터미널의 대화

아래는 실제 클라이언트 출력의 대화 부분을 발췌한 기록입니다. 색상 ANSI 코드와 캐리지 리턴을 제거했습니다. 입력 프롬프트가 수신 메시지와 겹치는 현재 구현의 동작은 그대로 표시했습니다.

클라이언트 A:

```text
ID: demo-alice
PW:
인증 성공! 채팅을 시작합니다.

[나]:
[알림] demo-bob님이 입장하셨습니다.
[나]: hello from alice
[나]: [demo-bob]: hello from bob
```

클라이언트 B:

```text
ID: demo-bob
PW:
인증 성공! 채팅을 시작합니다.

[나]: [demo-alice]: hello from alice
[나]: hello from bob
```

A가 입력한 메시지는 B에, B가 입력한 메시지는 A에 발신자 ID와 함께 표시되었습니다. B가 `quit`로 종료했을 때 A에서 퇴장 알림을 받았고, A도 `quit` 입력으로 정상 종료했습니다.

## 검증한 항목

| 항목 | 확인 결과 |
| --- | --- |
| 계정 환경변수 검증 | 설정 누락, 잘못된 JSON, 빈 객체, 객체가 아닌 값, 빈 비밀번호를 넣으면 시작하지 않음 |
| 로그인·입장 알림 | 실제 클라이언트 두 개의 로그인과 다른 접속자의 입장 알림 확인 |
| 양방향 채팅 | 두 실제 클라이언트의 송신·수신 출력 확인 |
| 인증 실패 | 서버에 잘못된 비밀번호를 전달하면 거절 응답 후 연결 종료 |
| 중복 접속 거절 | 새 연결에서 `n`을 선택하면 새 연결을 닫고 기존 세션의 메시지 전달 유지 |
| 중복 접속 교체 | 새 연결에서 `y`를 선택하면 기존 연결에 `quit` 전달 후 연결 닫힘, 새 연결에서 메시지 전달 확인 |
| 클라이언트 종료 | `quit` 입력으로 정상 종료, 상대 클라이언트에서 퇴장 알림 확인 |
| 문서의 계정 입력 명령 | 실제 터미널에서 ID·가려진 비밀번호를 입력해 서버 시작, 비밀번호가 출력되지 않음 |
| 백그라운드 시작 | 다른 작업 디렉터리에서 `start.sh --log` 실행 후 로그인 가능 |
| 중복 시작 | 실행 중인 서버의 PID를 유지하며 추가 서버를 실행하지 않음 |
| 백그라운드 중지 | 저장된 PID로 종료 요청, 수신 포트 닫힘과 PID 파일 제거 확인 |
| 다른 프로세스 보호 | PID 파일이 다른 프로세스를 가리키면 중지 요청을 거절 |
| 구문·문서 링크 | 서버·클라이언트 Python 구문, 두 스크립트의 `bash -n`, 상대 문서 경로 확인 |

중복 접속과 인증 거절의 서버 처리 검증에는 로컬 소켓 테스트 연결도 사용했습니다. 클라이언트 단독 검증에서는 로컬 모의 서버로 인증 성공·실패, 메시지 송수신, 종료를 추가 확인했습니다.

이 기록은 로컬 기능 확인 범위입니다. 외부 서버 운영 상태, 부하·장시간 동시 접속, TLS, TCP 메시지 분할·병합에 대한 안정성은 검증하지 않았습니다. 관련 구현 제한은 [README](../README.md#현재-구현-범위)에 정리했습니다.
